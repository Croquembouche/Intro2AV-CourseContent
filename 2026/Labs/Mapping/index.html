What does the algorithm calculate?

This page replays calculations made from the recorded frames. Playback and overlays run locally in your browser. The estimators run during data preparation. Changing display controls does not rerun pose estimation.

The visual demo builds a sparse map with monocular odometry and triangulation. The LiDAR demo registers scans against a local map. Full SLAM adds map reuse, loop verification, and global optimization. This short clip demonstrates local mapping without a loop closure.

Try it in class
  1. Pause visual mapping at frame 30. Click a green track, then find its highlighted landmark in the map.
  2. Hide unused observations. Compare how many tracked features actually constrain the pose.
  3. Switch to LiDAR. Turn match lines on, step forward, and inspect the cyan surface samples and their map correspondences.
  4. Turn map accumulation off and on. Explain why registering each new observation is necessary.
  5. Record one visual failure condition, one LiDAR failure condition, and the map type each produces.

Checkpoint: the map grows as new observations arrive. Visual map units are arbitrary, while LiDAR map coordinates are in meters. The two maps use different local origins and must not be compared as aligned trajectories.

Data, scope, and sources

Image features come from Shi-Tomasi corners and pyramidal Lucas-Kanade tracking. A robust essential matrix initializes the map. Triangulation supplies 3D landmarks, and PnP RANSAC estimates later camera poses against those landmarks. LiDAR registration uses voxel samples, PCA surface normals, and robust point-to-plane ICP against the preceding eight scans.

No ground-truth pose supplies the estimated maps. This teaching implementation omits bundle adjustment, automatic loop closure, IMU integration, semantic filtering, and per-point LiDAR deskew. An orange track is rejected or unused by geometry, which does not identify a moving object by itself.
